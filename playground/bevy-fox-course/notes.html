Fox Locomotion & 6-Stage IK — Architecture Notes

rust · bevy 0.18 · math · zero-js notes ← launch live playground

These notes document the control harness, equestrian jump solver, and 19-bone procedural Inverse Kinematics pipeline inside crates/bevy-fox-course. The entire simulation runs in pure Rust with only Bevy 0.18 (3d + webgl2) — no external physics engine and no extra assets beyond the 3 embedded clips of Fox.glb.

Schedule Architecture (Bevy 0.18)

Locomotion, gait selection, jump ballistics, and gaze priority execute in a deterministic Update chain, publishing pure state resources into a zero-drift PostUpdate IK pass that brackets Bevy's built-in AnimationSystems before TransformSystems::Propagate.

1. Non-Holonomic Suggestive Steering & Reversal Braking

Rather than snapping velocity 1-to-1 to WASD, player keys act as a camera-relative suggested heading interpreted through quadruped momentum. Normal key hold stays capped near 1.75 m/s for the first 0.45 s so feathering stays effortlessly in Creep/Walk, then ramps at 2.8 m/s² to a comfortable 2.95 m/s canter. Holding Shift urges 5.6 m/s² acceleration up to 6.20 m/s, while C/Ctrl locks into a 0.72 m/s stalk.

Quadrupeds pivot tightly at a walk and carve sweeping arcs at a gallop, so maximum yaw rate narrows smoothly with forward speed v, and grounded motion advances strictly along the facing vector f = (sin θ, cos θ):

ωmax(v) = lerp(4.2, 1.45, smoothstep(0.5, 5.8, v))   [rad/s]
Rmin(6.2 m/s) = 6.2 / 1.45 ≈ 4.28 m
ωdes = clamp(4.8 · wrap(θtarget − θ), −ωmax, +ωmax)
vxz = v · (sin θ, cos θ),    corner scrub = 0.70 + 0.30 · max(0, cos Δθ)

If the player suggests a sharp reversal (dsuggested · fxz < −0.35) while running faster than 2.0 m/s, active braking drops target speed to 1.1 m/s at 7.5 m/s² so the fox collects and brakes before pivoting instead of crab-sliding sideways. 

// crates/bevy-fox-course/src/controls.rs
pub fn compute_max_turn_rate(speed: f32) -> f32 {
    let t = smoothstep(0.5, 5.8, speed);
    4.2 + (1.45 - 4.2) * t
}

// Active braking on sharp reversal (`dot < -0.35` at `speed > 2.0 m/s`).
if current_speed > 2.0 && suggested_dir.dot(fwd_xz) < -0.35 {
    return (1.1, 7.5, true);
}

2. Centripetal Lateral Banking & Spine / Tail Counterbalance

In Fox.glb local space (+Z forward, +X left, +Y up), turning left corresponds to positive yaw rate (ω > 0) and requires dropping the left side (+X) via a negative Z-axis roll. Centripetal lateral acceleration ac = v · ω drives the body lean directly:

φbank = clamp(−atan2(v · ω, 9.81) · 0.65, −0.32, +0.32)   [rad]

Simultaneously, Stage 2 curves b_Spine01_02 (55%) and b_Spine02_03 (45%) horizontally into the turn (±0.34 rad), while Stage 3 swings the three tail segments (b_Tail01_012 → b_Tail03_014) outward with cascaded exponential lag rates [10, 7, 5] so the tip whips smoothly behind each corner. Because the tail extends along −Z, a positive local Y rotation naturally swings its tip toward −X (outward right) on a left turn. 

// crates/bevy-fox-course/src/controls.rs
pub fn compute_bank_roll(speed: f32, turn_rate: f32) -> f32 {
    (-((speed * turn_rate).atan2(9.81)) * 0.65).clamp(-0.32, 0.32)
}

// crates/bevy-fox-course/src/ik.rs (Stage 3 cascaded tail lag)
let target_tail_yaw = (loco.turn_rate * 0.24).clamp(-0.55, 0.55);
let tail_rates = [10.0_f32, 7.0, 5.0];
let mut upstream = target_tail_yaw;
for i in 0..3 {
    state.tail_yaw[i].smooth_nudge(&upstream, tail_rates[i], dt);
    upstream = state.tail_yaw[i];
}

3. Continuous 5-Gait Hysteresis & Procedural Synthesis

Fox.glb contains only three embedded clips (Survey, Walk, Run). We synthesize five continuous gaits by pairing separate rising/falling hysteresis thresholds with a 0.14 s anti-chatter dwell timer and continuous procedural posture weights (creep_w, sprint_w):

Gait Enter (rising) Exit (falling) glTF Clip Playback Rate Blend
Idle default v ≥ 0.20 Survey 1.0 320 ms
Creep v ≥ 0.20 / stalk v < 0.14 Walk (v / 1.65).clamp(0.32, 0.72) 0 ms ↔ Walk
Walk v ≥ 1.15 v < 0.90 Walk (v / 1.65).clamp(0.68, 1.45) 240 ms ↔ Run
Run v ≥ 2.65 v < 2.25 Run (v / 4.20).clamp(0.62, 1.25) 0 ms ↔ Sprint
Sprint v ≥ 4.65 v < 4.15 Run (v / 4.20).clamp(1.10, 1.58) 0 ms ↔ Run

Because Creep ↔ Walk share CLIP_WALK and Run ↔ Sprint share CLIP_RUN, crossing those boundaries never restarts AnimationTransitions. Instead, creep_w lowers the pelvis by −0.14 m (flexing all four legs through 2-bone IK), drops the neck +0.24 rad, and counter-pitches the head −0.20 rad to keep eyes level; sprint_w reads ActiveAnimation::seek_time() to drive a phase-locked spine gallop wave across b_Spine01_02 and b_Spine02_03.

4. Bidirectional Show-Jump OBB & Parabolic Solver

Each of the 8 fences defines an orthonormal frame (nxz, txz) so every jump can be taken cleanly from either side. Transforming the fox's position gives signed normal distance dn and lateral gate offset dt, with approach normal a = sign(−dn) · nxz. Inside the dynamic takeoff window:

dtakeoff = clamp(0.92 + 0.29 · v + 0.45 · hrail, 1.38, 2.95)   [m]

A jump commits into a 0.22 s Gather preparation phase only when all five gates pass: inside rail width (|dt| ≤ half_w − 0.24), sufficient speed (v ≥ vmin), valid approach cone (f · a ≥ cos θmax), player intent alignment (> 0.25 so you can always peel off), and safe predicted touchdown inside PLAY_AREA_RADIUS. During Gather, both hind paws pin onto speed-compensated turf anchors directly under the coiling pelvis while the chest pitches upward and the front legs lift off early—producing a clean, repeatable launch regardless of prior running stride phase. Liftoff then solves an apex-targeted parabola under g = 11.5 m/s²:

yapex = ybase + hrail + 0.18 + 0.08 · spread
vy0 = √(2 g (yapex − y0)),    tup = vy0 / g
tdown = √(2 (yapex − yland) / g),    Tair = tup + tdown   (2-step terrain height iteration)

Horizontal launch speed scales within ±12% so apex lands over the fence center, clearing wide oxers and the triple bar. On touchdown, a near-critically damped second-order spring (k = 140, ζ = 0.88) absorbs impact into the pelvis over 0.26 s:

y″ = −k · y − (2 ζ √k) · y′,    vy,impact = clamp(0.28 · vy,touchdown, −2.8, −0.8) 
// crates/bevy-fox-course/src/jump.rs
let clearance_margin = 0.18 + 0.08 * obs.spread;
let y_apex = (obs.base_y + obs.rail_height + clearance_margin).max(start_y + 0.38);
let vy0 = (2.0 * JUMP_GRAVITY * (y_apex - start_y)).sqrt();
let t_up = vy0 / JUMP_GRAVITY;

// 2-step terrain height iteration for exact landing point & flight duration.
let mut total_time = 2.0 * t_up;
let mut land_xz = pos_xz + vel_xz * total_time;
let mut y_land = terrain_height(land_xz.x, land_xz.y);
for _ in 0..2 {
    let drop = (y_apex - y_land).max(0.05);
    let t_down = (2.0 * drop / JUMP_GRAVITY).sqrt();
    total_time = t_up + t_down;
    land_xz = pos_xz + vel_xz * total_time;
    y_land = terrain_height(land_xz.x, land_xz.y);
}

5. Zero-Oscillation Wing Avoidance (AvoidanceLock)

When approaching a fence too slowly, too obliquely, or aimed at a wing, naive potential-field repulsion oscillates left and right near dead center (dt ≈ 0). AvoidanceLock eliminates chatter by scoring a side once on refusal entry and locking it until the obstacle clears:

score = 1.4 · dt + 0.9 · (dsuggested · t) + 0.6 · (f · t)
side = +1 if score ≥ 0 else −1   (locked until cleared)
pclear = cfence + side · (wwing + 0.65)t + (0.65 + 0.5 · spread)a

The steering harness blends the player's suggested direction toward pclear with distance-based weight w ∈ [0.42, 0.88], eases speed by up to −32%, and aims Gaze Priority #2 at the avoided wing upright. A grounded 2D OBB capsule pushout (r = 0.38 m, disabled while airborne) guarantees slow creep input can never clip through a rail.

6. 6-Stage PostUpdate IK Pipeline

Before AnimationSystems evaluates keyframes each frame, restore_pre_ik_pose restores all 19 IK-driven bones to the previous frame's pre-IK snapshot so un-keyframed bones never accumulate rotational drift. After animation evaluation (and before TransformSystems::Propagate), apply_fox_ik runs six ordered stages:

  1. Pelvis, Pitch & Banking — blends 4-point terrain slope alignment with ballistic flight pitch, centripetal roll, creep crouch, gather coil, and landing spring.
  2. Spine Curvature, Gallop Wave & Bascule — adds horizontal turn bend, phase-locked sprint bounce, and a convex mid-jump bascule arch: sin(π u)1.4.
  3. Cascaded Tail Counterbalance — damped 3-bone whip follow-through and gait pitch.
  4. Priority-Stack Look-At — distributes roll-free slerp across b_Spine02_03 (15%), b_Neck_04 (35%), and b_Head_05 (50%) in priority order: Jump Focus > Avoided Wing > Turn Anticipation > Cursor/Firefly. Runs before front legs because front shoulders descend from b_Spine02_03.
  5. Hybrid Grounded / Airborne 2-Bone Leg IK — solves elbow/knee placement analytically via the Law of Cosines:
    cos α = clamp((l1² + d² − l2²) / (2 l1 d), −1, +1)
    pmid = proot + l1 cos(α)d̂ + l1 sin(α)b̂
    While grounded, stance feathering plants paws cleanly onto terrain_height(x, z) with hind Foot02 slope compensation. During Gather and Airborne (u ∈ [0, 1]), jump targets are anchored directly to each leg's shoulder/hip joint (root_pos_w) rather than the animated Run paw position—making every jump independent of mid-stride clip phase. Front paws lift early and fold strictly below the chest on ascent before reaching forward to catch the landing turf, while hind hocks push off down-and-back and tuck cleanly behind the pelvis with explicit metatarsal aiming (airborne_hind_foot_dir) so the knees and 31 cm hind feet never clip into the torso. On touchdown, Run syncs to its front-strike phase (0.50 s) and front legs plant ahead of the hind follow-through.
  6. Color-Coded Debug Gizmos (G) — renders suggested heading (cyan), blended steering (green), avoidance flow (magenta), obstacle approach gates (green/amber), ballistic trajectory (gold), and full 19-bone IK chains.
// crates/bevy-fox-course/src/ik.rs
// Root-anchored fox-local (dy, dz) jump keyframes from shoulder/hip (meters at FOX_SCALE = 0.02).
pub fn airborne_leg_root_target(is_front: bool, is_left: bool, u: f32) -> Vec3 {
    let u = u.clamp(0.0, 1.0);
    if is_front {
        let ue = (u + if is_left { 0.03 } else { -0.03 }).clamp(0.0, 1.0);
        const FRONT_KEYS: [(f32, Vec2); 5] = [
            (0.00, Vec2::new(-0.52, 0.16)),
            (0.28, Vec2::new(-0.39, 0.14)), // tight tuck strictly below chest
            (0.52, Vec2::new(-0.46, 0.21)),
            (0.76, Vec2::new(-0.68, 0.28)),
            (1.00, Vec2::new(-0.80, 0.24)), // front-first landing reach
        ];
        let p = sample_curve_vec2(&FRONT_KEYS, ue);
        Vec3::new(0.0, p.x, p.y)
    } else {
        let ue = (u + if is_left { -0.02 } else { 0.02 }).clamp(0.0, 1.0);
        const HIND_KEYS: [(f32, Vec2); 5] = [
            (0.00, Vec2::new(-0.56, -0.38)), // takeoff drive off planted turf
            (0.18, Vec2::new(-0.50, -0.48)), // explosive rear thrust
            (0.50, Vec2::new(-0.34, -0.44)), // hock tucked behind pelvis (zero belly clip)
            (0.78, Vec2::new(-0.50, -0.28)),
            (1.00, Vec2::new(-0.64, -0.18)), // staggered hind touchdown
        ];
        let p = sample_curve_vec2(&HIND_KEYS, ue);
        Vec3::new(0.0, p.x, p.y)
    }
}
